# 部署文档与代码说明

## 1. 运行环境

| 项 | 要求 |
| --- | --- |
| Python | 3.10 ~ 3.12（开发与验收使用 3.12.10） |
| 操作系统 | Windows 10/11、Linux、macOS 均可；中文字体（Windows 自带 simhei/simkai/STXINGKA 等）仅样本生成器需要 |
| 内存 | 单进程峰值 < 500MB（处理 2400px 以内图像） |
| 依赖 | Python 依赖见 `requirements.txt`；Node.js 22+ 与 `eval/tools/package-lock.json` 提供的 resvg 用于标准 SVG 渲染 |

安装：

```bash
python -m venv .venv
.venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
npm ci --prefix eval/tools
```

自检：

```bash
python -c "import app.main; print('ok')"
python -m pytest tests -q
python eval/run_acceptance.py -o out/acceptance --repeat 2 --repeat-samples 2
```

## 2. 启动方式

### 2.1 开发 / 单机使用

```bash
python -m app.main                  # 127.0.0.1:8000
uvicorn app.main:app --port 8765     # 本轮开发服务端口
```

本机双击 `start_development.cmd` 可在 8765 启动。服务运行时访问 `/validation` 查看验证页。启动前设置 `ZIJI_EVIDENCE_DIR` 指向本轮 reports 文件夹，原始报告会以 `/evidence/` 提供只读访问。端口已被占用时应检查已有服务，避免重复启动。

SVG 渲染由一个常驻 Node/resvg 子进程处理，同步锁保持请求与响应一一对应。服务退出会关闭任务队列和渲染进程。开发验证使用固定进程；改完代码后重启，避免 Windows 下自动重载遗留旧进程。

### 2.2 局域网 / 生产

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1
```

注意事项：

- 当前任务和样本缓存保存在进程内，部署使用一个 worker。异步转换队列默认两个工作线程，总容量 10，队列满返回 HTTP 429；终态任务最多保留 64 项、保留一小时。多进程部署须先接入共享任务存储并验证创建、查询、取消。
- 服务默认本地监听，不做鉴权。放到内网或加一层反向代理（Nginx / Caddy）并补齐认证与限流。
- 隐私要求高时按 6.4 节做私有部署：整条链路无外部网络调用，图片不出本机。

### 2.3 仅供内网使用的反向代理示例（Nginx）

```nginx
location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    client_max_body_size 20m;   # 单文件上限 5MB，多文件批量请按需放大
}
```

## 3. 接口清单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 前端页面 |
| GET | `/api/health` | 健康检查 |
| GET | `/validation` | 开发验证报告页面 |
| GET | `/api/validation` | 当前验证结果 JSON |
| GET | `/api/providers` | 第三方服务配置状态，不含凭据 |
| POST | `/api/provider/vectorizer_ai/convert` | 显式调用官方 Vectorizer.AI 服务 |
| GET | `/api/presets` | 档位、引擎、导出格式与默认参数 |
| GET | `/api/samples` | 内置样本列表（含缩略图地址） |
| POST | `/api/convert` | 单张转换：返回 SVG 源码、指标、质量报告、对比图（base64 PNG）、裁切对齐原图（base64 PNG） |
| POST | `/api/batch` | 批量转换，最多 100 张；返回 ZIP，响应头 `X-Batch-Summary` 带汇总，逐项指标和原图映射写入 ZIP |
| POST | `/api/export` | 把已有 SVG 转成 PDF / EPS / AI（PDF 兼容） |
| POST | `/api/sample/{name}/convert` | 直接转换内置样本，字数与文字取自 manifest |

`POST /api/convert` 表单字段：`file`、`preset`(quality/balanced/compact)、`engine`(auto/contour/vtracer)、`tolerance`、`max_nodes`、`max_colors`、`gradient_levels`、`filter_speckle`、`corner_angle`、`smooth`、`auto_verify`、`strict_input`、`with_preview`、`glyph_count`（真实字数，选填）、`spot_colors`（专色 HEX 逗号分隔，选填）。

响应指标关键字段：`checks`（含 `node_50_500`、`no_breaks`、`no_specks`、`spur_ratio<=0.02`）、`checks_truth`（对真值口径）、`input_invalid`/`input_invalid_reasons`（需求 5.6 判定）、`glyph_count`/`glyph_source`、`subpath_count`/`node_floor_estimate`、`redundant_anchor_ratio`、`truth_shape_iou`。

批量请求额外支持 `fmt`(svg/pdf/eps/ai) 与多文件字段 `files`。

## 4. 处理流水线

```
输入图片
  └─ 解码 & 尺寸/体积校验（PNG/JPG/WEBP，≤5MB，边长≥500px）
      └─ 预处理 preprocess.py
          背景扣除（边界 k-means 估背景色 + 距离软阈值 / alpha 通道）
          前景判据：与可见背景色差 >20（噪声背景按边缘离散度自适应抬高）；
          候选字色覆盖小面积装饰色（如卡通字白色装饰点）
          CLAHE 对比增强 → 双边滤波 + 中值去噪（仅用于分层，颜色取原始像素）
          噪点连通域过滤 → 倾斜校正 → 主体外接矩形自动裁切
          质量与异常判定：主体占比、背景离散度、主体区模糊度、过曝、照片类识别
      └─ 矢量化 vectorize.py
          渐变型 → 单轮廓 + linearGradient/radialGradient（先剔除描边等纯色层再拟合）
          渐变+描边 → 渐变本体层 + 描边纯色层（需求 5.3）
          平面/多色 → 主色提取 → 标签扩散 → 逐层轮廓 → 节点预算（最多 3 轮重试）
          专色匹配（选填）→ 按字分组输出（每字一个 <g>，内含颜色子层）
      └─ 指标复核 metrics.py
          自参照口径 + 生成器真值口径；轮廓/特征/节点/颜色/色阶/内孔/
          轮廓杂讯（断笔、碎点、毛刺）/冗余控制点；XML 解析式格式检查
      └─ 输出
          SVG（viewBox + xmlns + 按字命名分组 + evenodd 填充，标题转义）
          AI（PDF 兼容）/ PDF（原生路径、渐变、填充透明度）/ EPS（PostScript Level 3 原生渐变）
          对比图 PNG、裁切对齐原图 PNG、指标 JSON
```

## 5. 关键算法说明

**轮廓拟合（svgutil.py）**：闭合轮廓先按端点闭合的 RDP 简化；每个顶点的转角超过阈值判为角点，角点处断开平滑；角点之间用 Catmull-Rom 转三次贝塞尔；节点超预算时按 1.28 倍逐步放宽容差重拟合，直到回到上限内。

**主色分层（vectorize.py）**：主色只在笔画实心区（腐蚀 2px）统计，避免抗锯齿混色被当成新颜色；4bit 量化桶按占比筛出真实颜色，再用 Lab 距离阈值聚类合并近似色；未被指派的前景像素通过标签膨胀向边缘扩散，因此分层结果能完整覆盖前景、不会出现边缘杂色层。绘制顺序按面积从大到小，上层图层向外扩 1px（不越过前景轮廓）以盖住层间缝隙。

**渐变判定**：先剔除占比 ≥18% 的单一纯色层（描边/底色），对渐变本体做亮度方向（或径向半径）的线性拟合；要求合并 R² ≥ 0.78、相邻色阶无跳变、箱内方差解释度 ≥ 0.6、离梯度像素比例 ≤ 15%。两遍拟合：第一遍方向被杂色拉偏时，用分箱中位数剔除离群像素后重拟合。色阶颜色取未经 CLAHE 的原始像素。

**节点预算**：单条轮廓预算 = min(单字上限, 2.6×√面积)；整图超预算时按「先只放宽容差 → 再逐级归并小色层」最多重试 3 轮（单轮收益 <15% 提前停止），最终取节点最少的一版。内孔用独立低门槛与收紧容差保面积，避免小孔被填实。节点下限由子路径数量决定（每条轮廓 ≥6 锚点），报告中的 `node_floor_estimate` 给出下限估计。

**专色匹配**：指定专色 HEX 列表后，平面色层与专色通道偏差 ≤3% 时替换为专色值（渐变层不参与）。

**按字分组**：路径按空间位置 k-means 聚成每字一组，输出 `glyph-N` 分组（name 取真实文字），每字内含各颜色子层，适配 Illustrator 单字选中编辑。

**引擎自检**：自动模式先检查轮廓 IoU，低于 0.93 时比较 vtracer。候选须提高至少 1.5 个百分点，同时通过颜色、局部区域及孔洞、节点上限和独立阴影层保护检查，才会替换。

## 6. 运维要点

### 6.1 性能基线（本机实测，Windows / Python 3.12，`--preset balanced`）

| 场景 | 结果 |
| --- | --- |
| 25 组样本单张平均 | 2062 ms（最慢 6152 ms，12_shadow 多层阴影触发 3 轮节点重试） |
| 25 组样本批量总耗时 | 68.8 s，平均 2753 ms/张 |
| 100 张批量（实测，25 组 ×4） | 290 s（2900 ms/张），低于 10 分钟上限 |
| 重复转换一致性 | 10 次 × 25 组，轮廓偏差 0.00% |
| 浏览器一致性 | Chrome/Edge 无头实测：边界平均偏差 0.58px |
| 内置示例 | 默认关闭后台预热；可设置 `ZIJI_WARMUP=1` 启用，缓存响应单独标记，不能充当转换性能证据 |

上表为历史版本诊断记录。100 张记录使用 25 组重复四份，尚未满足 100 张不同合规素材的正式验收要求。当前候选版的验证见 `docs/候选版验证说明.md`。

### 6.2 容量与限流建议

- 当前使用单 worker 和线程队列；同步单张、批量转换及导出在工作线程中执行。
- 单张最大 5MB，严格输入要求至少 500×500。超过处理画布上限时的自动缩放会记录到来源变换字段。
- 批量接口最多 100 张，最多三路转换，参数在批次开始时固定。ZIP 在内存中生成，输出重名会加后缀，`_batch_summary.json` 保存原文件与输出文件的映射。

### 6.3 日志与产物

- 服务日志走 uvicorn 标准输出，无额外文件写入。
- CLI 会把 SVG、PDF/EPS/AI、对比图、指标 JSON 写到 `-o` 指定目录；批量额外生成 `_batch_summary.json`。
- 验收证据：`out/acceptance/`（验收报告）、`out/browser_render/`（浏览器复核）、`out/export_check.json`（导出校验）、`out/batch100/`（100 张实测）。

### 6.4 私有化与合规

- 全链路本地计算，无外部 API 调用；若替换为云端矢量化 API，需要改 `vectorize.py` 引擎注册处并评估数据出境风险。
- 商业字体 / 品牌字标场景建议整机私有部署，禁止将素材写入公网对象存储。

### 6.5 验收与复核

```bash
python eval/run_acceptance.py -o out/acceptance --repeat 10 --repeat-samples 25  # 硬指标 + 真值口径 + 稳定性 + 速度
python eval/browser_render_check.py -o out/browser_render                         # Chrome/Edge 无头渲染一致性
python -m pytest tests -q                                                          # 核心口径自动化测试
```

`eval/browser_render_check.py` 用本机安装的浏览器无头渲染 SVG（灰底页面，白色元素可比），与内部栅格化对比掩膜 IoU 与边界距离；未安装的浏览器与 Safari/Illustrator 在报告中列为待用户验证。`eval/browser_check.py`（resvg 版）为旧版工具，保留但不再是主复核手段。

### 6.6 扩展方式

- 新增矢量化引擎：实现 `vectorize_xxx(prepared, opts) -> (SvgDocument, stats)`，在 `vectorize()` 的选择逻辑里注册即可，引擎输入统一是预处理后的 RGBA + 蒙版。
- 新增导出格式：在 `export.py` 增加 `svg_to_xxx(svg_text) -> bytes`，在 `service.convert_to_format` 与本文件第 3 节接口中挂上。
- 相邻场景（图标、线稿）：同一条管线可直接用，仅建议把「角点判定角」调大、颜色层上限调小。

### 6.7 Vectorizer.AI 可选配置

适配器调用官方 `https://vectorizer.ai/api/v1/vectorize`，使用 HTTP Basic 认证。设置以下服务环境变量后重启。

```powershell
$env:VECTORIZER_API_ID = "你的 API Id"
$env:VECTORIZER_API_SECRET = "你的 API Secret"
$env:VECTORIZER_API_MODE = "test"
```

`test` 是默认模式，免费但有水印。`production` 会消耗服务账户额度。使用 Swagger `/docs` 中的 `/api/provider/vectorizer_ai/convert` 上传文件，返回 SVG 与服务耗时及扣费响应头。凭据缺失时明确返回 422，普通本地转换保持本地执行。

本轮没有配置真实账户凭据，因此第三方适配器通过了请求契约及错误处理测试，生产服务质量与时延尚未验证。公开网页演示已完成飞白图片预览，下载跳转订阅页面。官方文档为 `https://vectorizer.ai/api/documentation`。

### 6.8 当前开发验证

当前报告以 `/validation` 与 `docs/开发环境验收记录.md` 为准。上文性能表保留为历史记录。清洁输入直接参考原始像素，预览和指标采用 resvg；PDF 柔边展开后使用 MuPDF 回渲检查，EPS 使用独立 Ghostscript 验证。

飞白节点与纹理、部分立体字特征和局部拓扑仍有失败。Safari 实机、Illustrator 2020+ 编辑和非技术人员首次使用仍待独立验证。
